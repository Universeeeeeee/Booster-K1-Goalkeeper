# 阶段 C：K1 基础速度控制验证

已完成独立 K1 模型中的速度控制验证：98 个工况，每个重复两次；两种步长均没有跌倒，所有运动后的零速度阶段均恢复稳定，24个旋转初始朝向工况的方向正确，重复轨迹逐值一致。部分指令没有通过平均速度跟踪判据，不能把未跌倒等同于指令有效。

## 复现与交付

```bash
.venv/bin/python scripts/validate_velocity.py
.venv/bin/python -m pytest -q
```

完整验证按低到高执行指令梯度，两种物理步长都重复两次。默认保存到 `reports/velocity_validation/`：

- `results.json`：来源/版本/哈希、协议、判据、全部工况与阶段结果。
- `report.md`：通过的指令点及每个工况的简表，脚本自动生成。
- `dt_2ms/`、`dt_1ms/`：每个工况的 `summary.json` 和 `trajectory.npz`，包含每个物理子步的状态和力矩。
- `tests.txt`：本轮全量回归结果，**141 passed**；原有107项测试保留。

可单独复查工况，使用新的输出目录：

```bash
.venv/bin/python scripts/validate_velocity.py --case left_0.2 --output results/check_left
```

`--repeats 1` 可用于诊断，但不会标记已验证重复性。重复性使用相同 seed=0、初始状态和指令序列，比较所有记录数组的SHA-256，不比较压缩文件的时间戳。本轮保存的98个工况对应196次独立执行；没有随机扰动、训练或参数调优。

## 协议与判据

直接复用 `k1_goalkeeper/walk_controller.py` 和原官方 `k1_walk.pt`/`LocomotionPolicy`。观测、历史、动作处理、滤波、PD与力矩限幅均未改。记录器仅包装调用以读取数据；原始PD需求的公式只用于记录限幅前需求，不用于产生或写入控制输出。实际输出仍由原控制器计算。

| 项目 | 设置 |
|---|---|
| 模型 | 原始官方 `K1_22dof.xml`，自由基座，原关节/惯性/电机参数 |
| 策略周期 | 20 ms / 50 Hz |
| 物理步长 | 官方2 ms，decimation=10；原模型1 ms，decimation=20 |
| 单方向工况 | 2 s零速度准备 + 6 s运动 + 5 s零速度恢复 |
| 指令梯度 | 前进0.05→0.8；后退−0.05→−0.28；双向横移0.05→0.25 m/s；双向转向0.1→0.8 rad/s |
| 坐标验证 | 初始yaw=0°、90°、180°，验证正反平移和正反转向 |
| 切换 | 前进加速/停止/后退/停止；左右横移反向/左右转向/停止 |

所有梯度均低于官方上限；出现稳定性失败时停止增加该方向的幅值。每段运动舍弃前2秒作为过渡，后4秒用于稳态统计；4秒切换段统计后2秒。每次独立执行重置策略历史与模型状态，切换段之间不重置历史。

预设判据没有根据结果放宽：

- 稳定：基座z≥0.3 m，机身倾角≤60°，无非有限状态、MuJoCo BAD警告或自动重置。
- 持续响应：稳态指令轴的实际/指令速度比在0.5–1.5内；起步几厘米的位移不够判定持续运动。
- 平均跟踪：指令轴平均误差≤`max(0.05 m/s或0.08 rad/s, 指令幅值×30%)`；非指令平移轴≤0.05 m/s、角速度≤0.1 rad/s。另保存瞬时RMSE，步态波动没有从数据中删除。
- 停止恢复：每一个运动后的零速度段均检查；末2秒平均平移/角速度≤0.05 m/s、0.1 rad/s，高度≥0.45 m、倾角≤10°，并找到连续1秒的低速区间（5个0.2秒窗口）。停止延迟表示该区间开始的时刻，确认需继续观察一秒。
- 力矩质量单独报告：每个物理子步比较限幅前PD需求与任务力矩上限。5%的单关节稳态饱和比例仅是本轮质量观察门槛，不是官方标准或跌倒判据。

## 坐标系与测量核对

平移指令在机身坐标系中：**+X前进，−X后退，+Y左移，−Y右移**。正角速度对应从上方观察的逆时针转向。90°、180°初始朝向下，平移方向随朝向旋转，转向符号保持正确。右侧守门朝向世界−X时，机身+X对应世界−X，机身+Y对应世界−Y。

自由关节线速度为世界坐标；使用完整机身姿态转换到机身坐标。角速度原本在机身坐标。主跟踪统计采用机身vx/vy/omega_z，另外保存世界竖直角速度及从展开的航向角得到的变化率；倾斜时这三个角速度不能混用。

发现只在50 Hz策略边界采样可能发生相位偏差，例如2 ms下的小前进指令曾显示约−0.1565 rad/s的边界角速度均值，但逐物理步均值与航向变化约−0.005 rad/s。因此本轮所有速度和饱和统计均使用物理子步数据，并以位置差分交叉核对；机身平移速度与位置差分的最大均值差约 **3.02×10⁻¹³ m/s**。独立检查也确认原始PD需求限幅后的输出与实际施加的关节力矩一致。

## 局限与守门用途

**可以复用：**已测的横移、前进、后退、原地转向和停止恢复可作为守门站位调整的运动底座。原模型1 ms步长下，两组速度切换均通过本轮判据；0.4 m/s前进和已测横移/转向的力矩余量也比2 ms更好。

**存在局限：**

- 平移指令幅值≤0.1 m/s、前后0.15 m/s及转向0.1 rad/s主要产生短暂姿态/位置变化，随后基本站住。不能依赖这些微小指令作精细位置校正。
- 0.2 m/s前进明显低于期望速度；0.3 m/s前进处于边界。1 ms下0.3前进平均0.2086 m/s，略低于固定判据所需0.21；−0.25后退平均−0.1745，略低于所需−0.175。切换历史还会改变这些边界结果，报告保留失败状态。
- 2 ms下最高肘pitch饱和比例约**95.25%**，两组速度切换的平均跟踪判据也未全部通过，尽管均保持稳定并完成停止。1 ms消除了本轮相关肘部高频饱和，但0.6/0.8前进的踝pitch仍约6.0%/9.05%饱和，较快运动的余量有限。
- 横移伴随侧向之外的位移和航向漂移，尤其2 ms下明显。速度输入是粗运动指令，精确守门站位仍需要后续位置/朝向闭环验证；本轮没有实现该闭环。
- 结果来自独立机器人和平面地面。它不能验收球门附近的定位、快速扑救或足球撞击后的平衡。阶段D/E尚未执行，也没有训练新策略。

后续场景验证优先沿用已有的1 ms步长，并以横移0.15/0.2/0.25、前进0.4、转向0.2/0.4等已测指令点开始。保留低速死区、停止距离和边界误差约束，不能只按指令值推算实际到位时间。
