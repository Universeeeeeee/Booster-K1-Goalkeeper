```bash

.venv/bin/python -m pytest -q
.venv/bin/mjpython scripts/visualize.py --control-mode k1_walk --camera goal_front
```

## 实现和坐标

`SceneSimulation` 与 `K1WalkController` 共用同一 `MjModel/MjData`。场景每次调用 `step()` 仅推进一个1ms物理步；每20步调用一次官方策略（20ms），每物理步执行官方PD。控制器拆出 `compute_targets/apply_control/finish_physics_step`，独立 A/B/C 的原 `step()` 继续按原时序组合这些操作。独立对照证明拆分后的目标、状态、PD力矩和策略历史与原接口逐位一致。

官方观测、历史、关节顺序、默认姿态、动作缩放、滤波、PD增益和限幅保持原样。读取和写入通过关节名称、`jnt_qposadr`、`jnt_dofadr` 及具名执行器映射完成；足球额外7个qpos、6个qvel不会进入K1策略。每次场景重置先恢复全场，再按场景初始自由基座位置/四元数初始化K1官方关节姿态，策略仅在重置时清空历史。

初始位置为世界 `(10.4,0,0.55369)` m，航向180°。机身+X指向世界−X，机身+Y指向世界−Y，正yaw俯视逆时针；转向后平移指令随当前机身方向旋转。

球门坐标直接采用原URDF框架：右门原点世界 `(11,0,0)` m，门的+X为世界+Y（横跨门口），+Y为世界−X（指向场内），+Z向上。机器人初始球门坐标约 `(0,0.6,0.55369)` m。世界框架描述环境，球门框架描述守门任务，当前机器人框架负责速度控制。

## 验证结果与用途

| 指令与运动时长 | 实际世界位移/航向变化 | 结论 |
|---|---|---|
| 零速度30s | 最低基座0.546739m；最大倾角1.190623° | 可用于球门前站立 |
| vy=+0.15 / −0.15，3s | ΔY=−0.109 / +0.095m | 方向有效，短时响应弱，未通过C跟踪阈值 |
| vy=+0.20 / −0.20，3s | ΔY=−0.373 / +0.369m | 通过方向、跟踪和恢复，可用于横移 |
| vy=+0.25 / −0.25，3s | ΔY=−0.614 / +0.609m | 通过方向、跟踪和恢复，可用于横移 |
| vx=+0.40，3s | ΔX=−0.834m | 可用于向场内移动 |
| vx=−0.27，2s | ΔX=+0.244m | 后退方向有效，但短时跟踪不足 |
| yaw=+0.2 / −0.2，3s | +0.590 / −0.566rad | 可用于基础转向 |
| yaw=+0.4 / −0.4，3s | +1.256 / −1.228rad | 可用于基础转向，需考虑倾角 |
| 连续横移、停止、反向横移、双向转向、停止 | 保留历史，所有阶段完成 | 可连续操作；仍是速度控制 |

连续切换沿用C已通过的 `vy=±0.2`、`yaw=±0.6` 组合，并缩短运动、插入5秒停止；没有加入新策略。各工况分别重置，连续工况内部没有重置策略。

所有工况最低基座高度0.475104m，最大机身倾角8.007259°，最慢停止恢复1.2秒。停止恢复沿用阶段C判据：最后2秒平均机身速度 `|vx/vy|≤0.05m/s、|wz|≤0.1rad/s`，高度≥0.45m、倾角≤10°，并找到连续1秒低速的0.2秒区间；延迟是该连续区间的起点，还需观察后续一秒确认。所有运动阶段稳态窗口的逐关节力矩饱和比例为0，起步瞬态PD峰值与限幅另见JSON/NPZ。

集成验收与稳态跟踪单独评估：集成要求完成、方向响应（平移≥0.02m/转向≥0.05rad）、姿态稳定、停止恢复以及无意外接触；`mobility_usable` 继续使用阶段C原阈值。±0.15横移和2秒后退的集成通过不代表稳态速度跟踪通过。短时后退平均机身vx≈−0.156m/s，不能当作立即达到−0.27m/s。后续守门应考虑低速死区、起步延迟和停止后的剩余位移；尚未验证精确到位能力或受球撞击抗扰。
