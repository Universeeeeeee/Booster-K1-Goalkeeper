# H0：原生 K1 防御动作几何审计

**结论：优先使用官方原生躯干和远端臂碰撞；当前小幅抬臂、前伸候选不需要新增 collision。肩 pitch 根部没有有效碰撞代理，不能声称整个肩部或全部视觉表面连续覆盖。静态姿态不是动态安全证明，本审计没有运行控制器或动态防御动作。**

复现命令：

```sh
.venv/bin/python scripts/audit_defense_geometry.py
```

脚本直接从官方 `assets/booster_assets/robots/K1/K1_22dof.xml` 文件路径编译；从官方 deploy `k1.py` 读取关节顺序，并从本项目实际 `tasks/locomotion/robots/k1/__init__.py` 的 `K1WalkControllerCfg.robot.replace(...)` AST 读取覆盖后的 default_joint_pos 和 effort_limit，不导入、推理或运行 walk policy。输出为 `reports/defense_validation/geometry_audit.json`。本阶段只新增脚本、JSON 与本文；既有 E0 碰撞审计保持不变。

## 1. 原生覆盖与缺口

上身审计共有 **18 个 geom，其中 8 个有效、10 个仅视觉**。每条编译几何都与既有 `reports/collision_audit.json` 的 body、类型、局部位置、姿态、尺寸和 mask 相符。JSON 使用 E0 的 `k1_geom_N` 别名，同时保存官方独立编译模型 ID；两个模型的 ID 不可互换。

| 部位 | 原生有效碰撞 | 覆盖局限 |
| --- | --- | --- |
| 躯干 | `k1_geom_1` 箱体：半长 0.06×0.08×0.10 m；`k1_geom_2` 圆柱：半径 0.05、半长 0.05 m | 箱体在 trunk 局部 z=0.10 m；圆柱 z=-0.06 m。视觉 Trunk 与 logo 网格禁用，不能以视觉外壳替代代理 |
| 左肩 pitch 根部 | 无；`Left_Arm_1` 为 0/0 视觉网格 | 该 body 没有直接原生球碰撞面；相邻肩 roll/躯干是否先接触需由实际 contact ID 判定 |
| 左肩 roll | `k1_geom_10` 圆柱，半径 0.035、半长 0.034 m | 局部 x=-0.007 m、圆柱轴沿 x，仅局部代理 |

| 右肩 pitch 根部 | 无；`Right_Arm_1` 为 0/0 视觉网格 | 同左肩缺口 |
| 右肩 roll、肘与远端臂 | `k1_geom_17` 圆柱、`k1_geom_19/21` 凸网格 | 与左侧对应，mesh 的细小不对称保留 |

有效 geom 均为 `contype=1, conaffinity=1`。透明的躯干箱体依然参与碰撞；视觉 group 与 alpha 不能用于判断是否阻挡球。当前场景球的 E0 mask 是 1/1，原生 8 个上身有效 geom 都具备球碰撞 mask 资格；这里没有发射球或统计实际挡球接触。

**补充碰撞是否必要：**原生躯干/肘/远端臂候选已经有碰撞面，所以本阶段无需补充，也没有添加碰撞。若以后把“肩 pitch 根部直接接触”或“整片视觉外壳连续覆盖”设为目标，才需独立定义补充模型与验证；肩部缺口的必要性依赖目标，不能把它当作目前 native 动作无法研究的理由。

## 3. 自碰撞规则与静态检查

官方 `npair=0`、`nexclude=0`；没有显式 body exclude 或 geom pair。默认同 body/焊接 body 过滤及父子 body 过滤启用。8 个上身有效 geom 形成 28 对，其中 **23 对具备默认碰撞资格，5 对被结构过滤**：同 trunk 的箱体–圆柱 1 对；每侧 shoulder-roll–elbow-pitch、elbow-pitch–elbow-yaw 共 4 对。肩 roll 与 trunk 中间隔着 shoulder pitch body，属于祖孙关系，不因直接父子过滤而排除。JSON 列出每一对规则，不把 mask 匹配误认为全部自碰撞都已监控。

每个候选检查从默认姿态到终点的 11 个角度插值样本，只调用 `mj_kinematics`、`mj_comPos`、`mj_collision` 与距离查询；13 个候选共 **143 个样本**。全部时间仍为 0，所有上身角均在限位内，检测到的机器人自接触数均为 0。基座固定为场景 standing 参考高度 z=0.55369 m、姿态直立；这是用于世界高度换算的参考放置，没有将官方 XML 的 z=1 m 当作 standing。脚底支撑、真实站立、平衡与负载没有被验证。离散路径中没有检测到接触，也不能排除样本之间、被结构过滤的相邻几何、视觉外壳或实际执行轨迹中的重叠。

**测量层交叉核验：**当前 active 默认姿态，native CCD 的 `mj_geomDistance` 在躯干箱体–左/右肘凸网格分别给出约 0.048536/0.048486 m，而独立重新编译的诊断副本仅切换到 libccd 距离计算后端后，分别得到约 0.020771/0.025054 m。部分小幅候选的 native 距离查询还返回 0 m，原生 `mj_collision` 却没有自接触。诊断副本没有用于控制、步进或主模型几何；源 MJCF 和主模型参数不变。多个 geom 对的两后端结果差异超过 1 mm，故 JSON 分开保留两套距离，**不把任何一套数值当成认证的最小净空**；0 m 也没有自动升级成碰撞事实。后续验证必须记录原生 contacts，而非只看这个距离 getter。

## 4. 小幅单臂与双臂候选

候选修改仅存在于静态 data.qpos。侧向抬臂 raise：左 shoulder roll 增加 +0.15/+0.30，右减小 -0.15/-0.30；前伸 extend：选中侧 shoulder pitch 减小 -0.15/-0.30。双臂同时应用对应两侧角度，其余全部关节保持官方默认。

### air_high 的条件静态几何上界

为避免用小角度候选推断所有可能姿态，另用三角不等式构造与臂关节角、根姿态旋转无关的保守上界，忽略关节限位和碰撞限制，因此只会高估可达范围：

```text
肩 anchor 长度                 0.199923 m
+ shoulder-roll body 偏移长度   0.069372 m
+ elbow-pitch body 偏移长度     0.044428 m
+ elbow-yaw body 偏移长度       0.121500 m
+ distal native mesh 外接半径   0.228000 m
+ 数值裕量                     0.000001 m
= trunk 原点至 native 臂几何上界 0.663224 m
```

对两个肩 roll 圆柱和四个肘/远端 native mesh 分别计算；最大值来自远端臂。圆柱用 `||geom_pos||+sqrt(radius²+half_length²)`，mesh 用编译顶点相对所属 body 原点的最大欧氏距离，凸包没有超出这些顶点的范数上界。该界无需试大角度或跑动力学。

在固定 trunk 原点 z=0.55369 m 的条件下，任意臂关节角的 native 几何都满足 **z≤1.216914 m**。若 air_high 在机器人中心处球中心为 1.4 m、半径 0.11 m，球底为 **1.29 m**，至少仍有 0.073086 m 垂直间隔，因此这个固定高度条件下，抬臂无法触及该球。更一般地，只有当瞬时 trunk 原点 **z≥0.626776 m** 时，这个保守界才不再排除垂直重叠；达到阈值也不代表实际能接触。

这是条件静态排除结论，不能扩展为所有动态过程都“不可能”：base 上升/起跳、球轨迹实际高度变化、接触时刻必须单独测量。JSON 保存每个 geom 的偏移分解、外接半径和上界，H1 应用实际 crossing 时刻的 trunk/球高度检查该条件。

## 5. native 优先候选序列与阶段边界

建议仅作为后续提案，先默认躯干基线，再分别左/右单臂 raise 0.15，然后双臂 raise 0.15；其后分别左/右单臂 extend 0.15，再双臂 extend 0.15。0.30 候选由 H0 决定后进入已授权范围内的受控试验。每个动作都应保留 torso-only 对照，并依据实际球接触 geom ID 归类。

H0 决定后进行已授权的受控 walk-policy/arm-PD 试验，明确关节控制归属、切换与插值方案，再检查自由基座平衡、真实轨迹跟踪、力矩饱和、warning、自碰撞及球接触；本阶段没有运行混控，静态报告不替代 H1 动态证据。当前结论只能支持 **native collision 足够开展后续受控候选验证**，不能支持“动作已经安全”或“防御效果已经提升”。
