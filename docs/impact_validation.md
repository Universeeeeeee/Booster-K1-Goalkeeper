# 阶段 E：足球碰撞与 K1 抗扰验证

E0先核查警告和碰撞覆盖，再执行E1/E2。完成69个工况、138次执行：33个自由K1工况、33个完全相同发射状态的无机器人对照、3个固定K1对照；重复轨迹全部逐位一致。31个自由工况实际接触机器人，其中30个维持并确认恢复平衡，1个触发跌倒高度阈值；另2个为故意无接触的站立/横移对照。没有非有限状态、BAD警告或自动重置等数值异常。

原161项测试保留，新增26项后 **187 passed**。官方MJCF、所有策略部署文件、权重、球门URDF、足球参数、PD及A/B/C/D机器报告保持不变。本轮没有补建碰撞体或训练/修改控制策略。

## 1. E0前置核查

历史QVEL警告来自 `test_mujoco_silent_unstable_reset_is_error`：在无机器人模型中故意给足球X速度 `1e100m/s`，该模型DOF0是足球，不是K1。单独运行1项通过且复现相同警告；排除后原160项无警告。底层BADQVEL计数0→1，MuJoCo会把状态重置为有限值，而原 `run_shot` 仍抛正确异常；不能仅以重置后状态有限就判成功。正常2秒自由站立的全部8项MuJoCo warning计数为0。

加载的K1有44个几何：20个满足与足球碰撞的掩码规则，24个视觉几何 `contype=conaffinity=0`。没有排除球–机器人身体对；视觉Mesh不自动视作碰撞体。

| 区域 | 当前可用碰撞体 | 本轮接触实证 |
|---|---|---|
| 躯干 | box与下部cylinder | 正中、世界Y偏移±0.07m、横移时躯干冲击 |
| 头 | 两个启用碰撞的凸Mesh | head pitch区域2m/s |
| 双臂 | 肩roll cylinder、肘pitch/yaw凸Mesh | 左右前臂/elbow yaw区域2m/s |
| 双腿 | hip roll/yaw与膝局部cylinder、小腿局部box | 左右小腿2/4/8m/s |
| 双足 | 足底box | 左右足2/4/8m/s；球亦可能随后接触邻近小腿 |
| 肩pitch根部、髋pitch根部、踝pitch十字部 | 只有视觉Mesh，无直接碰撞几何 | **不可验证**；不能把未接触称为真实拦截失败 |

其他代理仅覆盖局部，不能保证整个视觉大腿/躯干/手臂表面连续封闭。启用碰撞的Mesh使用凸包，不能保证视觉凹陷的接触精度。完整清单及复现证据见 [碰撞覆盖审计](collision_audit.md) 与 `reports/collision_audit.json`。现有代理足以完成本轮必要部位测试，因此没有扩展模型。

## 2. 实验协议

完整足球场共用一个MuJoCo物理实例。自由K1复用 `SceneSimulation` 和官方控制器：physics_dt=0.001s、policy_dt=0.02s、decimation=20，每物理步PD。保留官方默认关节姿态、顺序、观测、历史、动作缩放/滤波、增益和限幅。只在创建新工况时重置；发射足球和切换速度均不重置策略。

所有自由工况先站立2秒。静止目标依据此时有效几何体实际世界位置生成发射状态：球表面距几何前缘约0.3m，球向世界+X运动，面对朝世界−X的K1。高球采用简单重力抛物线瞄准，足部采用地面滚动输入；没有持续施加外力。原半径0.11m、质量0.43kg、惯量、摩擦和软接触参数均保留。

横移组先执行2秒机身 `vy=+0.2m/s` 再发射，发射后继续1秒横移，然后零速度恢复。发射时实测已向世界−Y移动约0.190m，瞬时机身vy约0.293m/s，不能把指令值当作实际速度；完整位移/速度在 `preimpact_robot` 和轨迹中。

观察发射后6秒；原进球判定器持续记录首个整球越线事件，但进球后继续观察机器人恢复。跌倒定义沿用此前阈值：基座低于0.3m或机身倾角超过60°，记录首次事件并中止；不会重新初始化或修改策略掩盖结果。官方安全回退亦保持启用。提前停止后的未判定进球为`null`；恢复未确认不表示已证明永远无法恢复。

速度梯度从2m/s开始逐级增加；这些是实验选点，**不是FIFA官方速度值**。正面躯干在20m/s触发跌倒后，计划中的24、30m/s不再执行。没有证明点之间的连续速度范围、其他入射角、球旋转组合或真实机器人抗扰能力。

固定模型沿用原`fixed`场景的零关节姿态，作为刚体接触隔离；它与策略默认/稳定后的自由姿态不同，不能解释为同姿态去掉控制器。无机器人对照则使用对应自由工况完全相同的球位置、速度和旋转，以区分机器人造成的轨迹变化。

## 3. 平衡结果和限制

| 条件 | 已测初速度m/s | 平衡/恢复结果 |
|---|---|---|
| 正中躯干 | 2、4、6、8、12、16 | 全部维持并确认恢复；最慢恢复1.4s |
| 正中躯干 | 20 | 发射后约0.529s基座降至0.299702m，触发跌倒高度阈值；当时倾角24.696°，停止后的进一步恢复未观察 |
| 左右偏心躯干，世界Y±0.07m | 每侧2、4、8 | 全部维持并确认恢复 |
| 左右足、小腿 | 各2、4、8 | 全部维持并确认恢复，按实际接触体记录，不能仅按目标名称归因 |
| 横移vy=+0.2时躯干冲击 | 2、4、8 | 全部维持并确认恢复；恢复延迟0.6–0.8s |
| 头部、左右前臂 | 各2 | 全部维持并确认恢复；尚未测试这些部位的更高冲击 |

维持平衡判据是整个冲击观察期高度≥0.45m、倾角≤10°，无跌倒/策略停机/数值异常且工况完整。恢复沿用阶段C的 `recovery_metrics`：最后2秒平均机身 `|vx/vy|≤0.05m/s、|wz|≤0.1rad/s`，高度≥0.45m、倾角≤10°，找到连续1秒低速的0.2秒区间。恢复计时起点取最后一次机器人接触结束与零速度切换时刻的较晚者；延迟还需后续1秒观察确认。

16m/s正面工况全程最低高度0.459626m、最大倾角8.377600°，躯干法向冲量约8.907N·s；20m/s约11.911N·s，6ms接触段峰值约3226N，最严重关节的冲击后力矩饱和采样比例约42.8%，同时发生高度崩落。这里报告相关变化，不把饱和单独视作跌倒原因，也不宣称16m/s是安全上限。

## 4. 四项独立判据与进球一致性

1. **有效接触**：足球与已求解机器人接触约束有大于1e−6N的法向力，记录实际body/geom；仅视觉重合不算。
2. **轨迹改变**：对照相同发射的absent轨迹，位置差≥0.02m或速度差≥0.1m/s。与接触、恢复分开记录。
3. **维持/确认恢复平衡**：按前述姿态及恢复判据；跌倒也是有效实验结果。
4. **成功阻挡右门**：相同发射的absent工况进右门，而有机器人工况完整观察、发生物理接触且右门未进球，仅在本轮6秒窗口内成立。

30个未跌倒的自由接触工况均改变轨迹并在观察窗口守住右门；对应absent组均进右门。2个故意偏离机器人的对照仍保持稳定，但无接触、无机器人导致的轨迹变化，最终进右门：不能称为拦截成功。20m/s自由工况已发生接触及反弹，但因跌倒中止，是否最终守住右门和进一步恢复均未证实。

固定2/8/20m/s均发生接触和反弹。**固定20m/s反弹球随后在约6.357s进入世界X=−11的左门**，不是右门失守或穿过躯干。`goal`仍保留原判定器的任一门进球结果；新增`defended_goal`仅表示世界X=+11的右门进球，因此该例`goal=true`、`defended_goal=false`。不改变整球越线、门口范围或首个出界锁存逻辑。

## 5. 接触力和数值精度核查

每个物理步在原生求解后用 `mj_contactForce` 提取接触坐标下6维力/力矩；法向从geom1指向geom2。将接触基转到世界并根据球在geom1/geom2的位置确定球所受力，积分 `ΣF·dt` 得到线冲量，同时记录法向冲量、接触点、持续时间、峰值及碰撞前后速度。[MuJoCo接口说明](https://mujoco.readthedocs.io/en/3.3.7/APIreference/APIfunctions.html#mj-contactforce)、[接触结构说明](https://mujoco.readthedocs.io/en/3.3.7/APIreference/APItypes.html#mjcontact)。

独立核对 `m·Δv` 与所有球接触力（包含地面）加重力的逐步冲量，避免把地面冲量误归给K1。严格1e−6N·s门槛有6个工况未满足，最大2.313005e−5N·s，全部最差样本发生在球–地面接触；保留 `momentum_precision_passed=false`，没有放宽阈值。

对这6个工况另行原样复现并与底层状态交叉核对：

- 接触力总和与球平移DOF的 `qfrc_constraint` 最大差≤1.14e−13N。
- 实际Δv与原生 `qacc·dt` 最大差≤4.45e−16m/s。
- 残差与 `(m·qacc−qfrc_smooth−qfrc_constraint)·dt` 最大差≤2.23e−16N·s。

由此确认力重建和积分正确，残差来自原Newton有限动力学梯度。最差步球所在求解岛3次迭代后，代价改善5.214e−7低于原tolerance=1e−6，梯度仍有限；Newton以代价改善和梯度范数中较小者终止。[官方求解阈值说明](https://mujoco.readthedocs.io/en/3.3.7/XMLreference.html#option-tolerance)。没有调整求解器、控制器或足球参数。`experiment_valid`表示有限、可重复、有完整/明确终止记录的实验，不能替代严格动量精度通过标记。

软接触允许几何交叠：正中2m/s机器人接触最大约3.16mm，20m/s约35.92mm，未发现该躯干试验穿过代理仍向右门运动；高速度结果仍受现有软接触参数影响。足球接触参数未经实球碰撞/滚动标定，物理内部一致性不能等同于真实恢复系数、真实冲击力或任意高速无穿透保证。

## 6. 复现和数据

在项目根目录、现有 `requirements-walk.txt` 环境及固定官方资产下：

```bash
# E0先运行；保存源头测试和底层警告证据
.venv/bin/python scripts/audit_collisions.py --reproduce-tests
# 完整冲击、固定/absent对照及重复校验
.venv/bin/python scripts/validate_impacts.py
# 严格动量精度未通过工况的底层独立复核
.venv/bin/python scripts/audit_impact_solver.py
# 原161项+新增26项回归
.venv/bin/python -m pytest -q
```

`validate_impacts.py --output <目录>` 可另存，默认每工况重复两次。`audit_impact_solver.py` 读取默认报告目录；若另存，请针对该目录的JSON/场景/轨迹独立核对。`reports/impact_validation/results.json` 保存协议、版本、保护文件/代码哈希、重复哈希、四项判据和精度限制；`report.md` 为全工况简表，`tests.txt` 为最终回归输出。

每个工况保存 `summary.json` 与1ms分辨率的 `trajectory.npz`：球与机器人状态、世界/机身速度、原始PD/实际电机力矩、饱和、完整qpos/qvel。`contacts` 为独立接触样本表，15列依次是：物理步开始/结束时间、对方geom/body ID、接触点世界XYZ、球所受世界力XYZ、法向力、接触坐标力矩XYZ、距离（负值为交叠）。球角速度是球局部坐标；世界速度/进球判定沿用世界框架。连续接触段的实际部位、前后速度、时长与冲量另存JSON。

`solver_audit.json` 保存6工况独立底层核对及原轨迹哈希一致性。报告区分首次物理执行代码哈希与基于保存轨迹的最终判定代码哈希：最终修正右门/任一门区分和精度标记分类，没有重写或删除原始实验轨迹。

D阶段继续保留“意外球–机器人接触立即拒绝”的原规则，E记录器将这类接触作为预期测量；原射门入口和进球模块均未修改。

## 7. 后续守门工作的判断

现有碰撞体足以测试选定躯干、足腿、头部和前臂位置。若任务需要肩根、整段大腿、踝交叉或任意视觉表面可靠挡球，需要单独的场景碰撞扩展，再核对质量/惯量和站立回归；当前不能使用覆盖缺口评估真实扑救失败。

当前k1_walk可支持已测低中冲击条件下的基础站立与横移，但20m/s正面工况暴露高度崩落。扩大抗扰范围可能需要专门的支撑/缓冲动作或抗扰控制策略；在此之前应标定足球接触并明确几何覆盖，不能以修改官方PD把本轮跌倒“调没”。本轮未加入高层自动扑救、视觉感知、强化学习或真实部署。
