# Robot-Perception-Sim：Mac 感知仿真开发总计划（P0–P4）

**版本：** v1.2
**目标平台：** macOS + MuJoCo
**未来平台：** Linux + NVIDIA Isaac Sim
**参考相机：** Stereolabs ZED X，2.2 mm 广角双目
**研究范围：** 机器人本体视觉感知、传感器仿真、轨迹输入、数据记录与感知评测

---

## 0. 项目定位与仓库边界

### 0.1 仓库关系与复用原则（2026-10-20 用户更新）

**唯一仓库：** https://github.com/Universeeeeeee/Booster-K1-Goalkeeper

**唯一开发目录：** `Robot-Perception-Sim/`。其他目录仅供参考或复用，不修改其源文件和已有实验输出。

独立远端 `Universeeeeeee/Robot-Perception-Sim` 已弃用。本目录不建立独立 Git 仓库。

**原则：能参考、复用的，一律参考、复用；尽量不要增加额外负担。**

当前工作收缩为：在原有 K1 足球仿真环境中增加相机资产和采集接口。直接复用已有 K1 资产、`k1_goalkeeper.scene.build_scene`、`config/simulation.json` 和根目录 `.venv`；不重复建立机器人资产获取、场景框架、包安装或依赖环境。

SDK 选择：官方 ZED SDK 支持当前平台时优先使用；不支持时先采用 MuJoCo 双目采集接口。官方支持系统为 Windows、Ubuntu 和 Jetson Linux，当前 macOS Apple Silicon 使用 MuJoCo。该接口不冒充官方 SDK 的深度、跟踪或 IMU 能力。

初版 P0–P1 以本节最新约定为准。2026-10-21 用户进一步授权运动足球双目采集：只增加 P2 的已有物理射门视频与 0/10 ms 曝光对照；规则轨迹、CSV 回放及 P3–P4 完整路线仍留待后续。

### 0.2 核心目标

建立如下感知仿真链路：

```text
                    轨迹输入
                       |
             +---------+---------+
             |         |         |
          规则轨迹   实测轨迹   物理仿真
             |         |         |
             +---------+---------+
                       |
                 足球仿真场景
                       |
                Booster K1
                       |
                 头部 ZED X
                       |
               左右 RGB 图像
                       |
                目标检测/匹配
                       |
                  三维定位
                       |
                速度/轨迹估计
                       |
                Ground Truth
                   误差评测
```

其中，仿真真值和未来轨迹只能进入场景驱动、诊断或离线评测模块，不能直接作为正式视觉感知算法的输入。

### 0.3 当前明确不做

- 不开发机器人运控算法。
- 不训练 PPO、SAC 或其他运动策略。
- 不修改父目录既有项目的运动控制器、训练环境或已有实验。
- 不引入复杂的 RL 环境与奖励系统。
- 不在 Mac 上强行运行完整 ZED SDK。
- 不实现 Isaac Sim 后端。
- 不开发与当前目标无关的通用仿真框架。
- 不进行尚无实物依据的相机真实标定。
- 不追求高保真材质、光学噪声和复杂物理参数辨识。

遵循简单优先、独立验收、最小改动原则。

# P1：ZED X 双目相机建模与头部挂载

## P1.1 目标

在 K1 头部显式建立 ZED X 双目相机。

需要实现：

- 左右相机几何模型。
- 相机与 K1 头部的安装关系。
- 相机内外参。
- 同步双目图像渲染。
- 双目投影和三维几何验证。

当前 Mac 不支持官方 ZED SDK，采用 MuJoCo 双目采集接口；未来支持平台优先评估官方 SDK。

## P1.2 挂载位置

官方 K1 模型已包含：

```text
trunk
 └── aahead_yaw_link
      └── aahead_pitch_link
           ├── head_realsense_rgb_link
           └── head_booster_stereo_rgb_link
```

复用 `aahead_pitch_link` 下已有的 `head_booster_stereo_rgb_link` 光学坐标系，在其下挂载 ZED X 虚拟相机组件。

建议逻辑结构：

```text
aahead_pitch_link
 └── head_booster_stereo_rgb_link
      └── zedx_mount
           ├── zedx_left_camera
           └── zedx_right_camera
```

左右相机光心间距：

`baseline = 0.120 m`

相机挂载位置和方向需要独立配置。

已有 RealSense 和 Booster 相机坐标系可以作为安装位置参考，但不能直接当作 ZED X 的真实安装外参。

### 实现要求

- 相机与头部刚性连接。
- 头部 yaw/pitch 变化时相机跟随。
- 左右相机的相对外参保持固定。
- 不改变原始 K1 模型。
- 不添加会影响动力学的相机质量或碰撞体。
- 使用独立生成的场景文件。
- 不改动父目录既有项目任何文件。

## P1.3 相机成像参数

参考型号：

`ZED X 2.2 mm Wide`

初始配置：

| 参数 | 设置 |
|---|---|
| 左右目 | RGB × 2 |
| 名义基线 | 0.120 m |
| 水平 FOV 参考 | 110° |
| 垂直 FOV 参考 | 80° |
| 首选分辨率 | 960×600 |
| 参考帧率 | 60 fps（10 ms 曝光所用参考模式） |
| 曝光 | 10 ms 全局曝光，10 个子样本做 RGB 时间平均；曝光内按当前广义速度不变近似 |
| 畸变 | 理想零畸变对照 |
| 相机模型 | 针孔相机 |
| IMU | 本阶段仅预留参数位置 |

注意：

- 这些参数是名义参考，不是实机逐台标定。
- 不随意编造 \(f_x,f_y,c_x,c_y\) 的出厂数值。
- 采用一致的针孔模型，由选定 FOV、分辨率和像素约定计算内参。
- 如果水平、垂直 FOV 与像素纵横比不能完全一致，应记录采用的主约束和计算结果，不能暗中使用相互矛盾的参数。
- 未来可以使用 SDK 导出的真实标定替换名义参数。

建议使用 JSON 存储：

```text
config/cameras/zedx_wide.json
```

每个参数需记录来源或模型假设，至少区分：

- `vendor_spec`
- `nominal_model`
- `simulation_assumption`
- `device_calibration`

不要将零畸变的理想模型标识为 ZED X 真实镜头的完整畸变参数。

## P1.4 坐标系定义

至少建立：

- `world`
- `robot_base`
- `head_link`
- `zedx_mount`
- `left_optical`
- `right_optical`

统一使用：

\[
T_{WC}=T_{WB}T_{BH}T_{HC}
\]

相机标定采用常见的光学坐标约定：X 向右，Y 向下，Z 向前。

正确处理 MuJoCo 相机的局部 −Z 观察方向与光学坐标系之间的旋转关系。

所有矩阵必须明确：

- 从哪个坐标系变换到哪个坐标系。
- 平移单位。
- 四元数顺序。
- 旋转矩阵行列向量约定。

不要只依靠截图视觉效果验证坐标方向。

## P1.5 双目预览程序

新增：

```text
scripts/preview_stereo.py
```

建议命令：

```bash
.venv/bin/python Robot-Perception-Sim/scripts/preview_stereo.py \
  --output-dir Robot-Perception-Sim/results/stereo
```

如果 macOS 环境需要，可以使用 `mjpython` 执行。

生成：

```text
Robot-Perception-Sim/results/stereo/
├── left.png
├── right.png
└── metadata.json
```

`metadata.json` 至少记录：

- 模型和配置版本。
- 左右图像尺寸。
- 使用的内参。
- 左右相机世界位姿。
- 左右目相对外参。
- 双目采样时间。
- 足球世界坐标。
- 相机参数来源与假设。

本阶段仅静态截图，不要求实现实时视频。

## P1.6 几何验证

新增独立测试：

```text
tests/test_stereo_camera.py
```

必须验证：

1. 左右相机存在且可以按名称访问。
2. 左右光心基线与配置一致。
3. 光轴方向正确。
4. 左右相机相对外参正确。
5. 已知三维点的投影满足针孔模型。
6. 已知视差能够恢复正确的三维坐标。
7. 调整头部 yaw/pitch 后，左右相机刚性跟随。
8. 球位于预期视野内时可以在两路渲染图像中观察到。
9. 新增相机不改变官方机器人原有动力学参数。
10. 不引入真实 SDK 或运控依赖。

这里需要特别注意：

**初期头部运动验证应采用预设关节角＋运动学更新，而不是执行零力矩物理仿真。**

因为直接对自由机器人做零力矩 `mj_step` 会导致机器人失稳，而把所有关节删除又无法验证头部运动。

因此，可以为静态／运动学测试保留原始关节，仅设置关节状态、调用 `mj_forward` 并渲染；暂时不要求仿真物理推进。

### P1 验收标准

- 左右 RGB 图像成功生成。
- 双目基线为 120 mm。
- 相机光轴与机器人面向方向一致。
- 足球投影和视差符合几何计算。
- 相机跟随头部姿态变化。
- 独立测试通过。
- 文档记录所有名义参数和验证结果。
- 首版以水平 FOV 110°、960×600、方形像素为主约束，得到焦距约 336.10 px、垂直 FOV 约 83.50°；厂商参考值不当作实机标定。
- 左右相机使用平行光轴、相同内参，基线沿光学 X 轴。
- 使用独立渲染标记交叉验证解析投影，覆盖中央、边缘、多个深度及非零头部 yaw/pitch；记录像素误差和验收阈值。
- 给出距离与视差误差敏感度，区分几何精度和未来图像检测精度。

# P2：足球轨迹输入与回放

## P2.1 目标

实现三种轨迹来源：

1. MuJoCo 物理射门。
2. 规则生成的运动轨迹。
3. 外部实测三维轨迹回放。

三种来源应使用统一的输出数据语义，但不要求采用完全相同的物理执行方式。

## P2.2 轨迹数据约定

建议基础记录包括：

```text
timestamp_s
position_world_m
velocity_world_mps
source
```

根据具体来源，可增加：

- 足球姿态。
- 角速度。
- 测量有效性。
- 数据来源。
- 轨迹或实验 ID。

其中位置、时间戳为主要字段。

外部轨迹如无速度测量值，可以经过明确记录的方法估计速度，但不能假装速度是直接测量所得。

原始数据文件必须能够单独解析，不依赖 MuJoCo 内部的 `qpos` 数组布局。

## P2.3 规则轨迹

至少支持：

- 匀速直线运动。
- 简单重力抛物线。

使用明确的初始状态和时间定义。

优先采用简单解析公式，不额外构建复杂轨迹规划器。

## P2.4 物理射门

参考旧项目：

`k1_goalkeeper/simulation.py`

复用已理解和验证的足球初始状态设置方法与 MuJoCo 自由体动力学。

物理模式中，足球状态由 MuJoCo 推进。

记录：

- 仿真时间。
- 世界坐标位置。
- 世界坐标线速度。
- 必要的旋转状态。

不得同时由外部轨迹和 MuJoCo 自由动力学修改同一个足球状态。

## P2.5 外部轨迹回放

第一版支持 CSV。

最小格式：

```csv
timestamp_s,x_m,y_m,z_m
0.000,6.0,0.0,0.8
0.010,6.1,0.0,0.85
0.020,6.2,0.0,0.89
```

实际数据采用独立文件。

功能：

- 检查时间戳严格递增。
- 检查数据单位。
- 拒绝 NaN、Inf 和非法字段。
- 根据明确的插值规则获得指定时刻球的位置。
- 不默认推算未定义区间以外的位置。
- 保留原始轨迹，不覆盖输入文件。
- 明确该模式为轨迹驱动，不将其碰撞结果宣称为真实物理碰撞。

初期只要求离线 CSV 回放。

实时网络轨迹、相机真机采集和复杂流式通信留待后续需求确定后开展。

## P2.6 测试

测试：

- 相同轨迹重复回放得到相同状态。
- 规则轨迹与解析参考一致。
- 外部轨迹在指定采样时刻正确插值。
- 轨迹时间和世界坐标单位正确。
- 非法文件产生明确错误。
- 物理推进和外部轨迹回放的状态所有权互不冲突。

### P2 验收标准

使用同一个 K1 双目场景，分别输入物理射门、规则轨迹和外部 CSV 轨迹，都能在指定时刻得到正确的球状态和对应的双目画面。

# P3：双目数据采集与 Ground Truth 记录

## P3.1 目标

建立独立于 MuJoCo 和 Isaac Sim 的感知数据协议。

核心原则：

**仿真物理时间、相机采样时间和感知处理时间分别定义。**

当前 MuJoCo 可以采用原有场景的 1 ms 物理步长，但相机采样率独立于物理采样率。

首选测试模式：

- 960×600。
- 60 fps。
- 120 fps。

考虑到 1 ms 的物理步长不能精确整除 60 Hz 或 120 Hz，必须记录实际采样时刻。

可以采用明确的离散采样调度，或在需要时通过状态插值取得目标时刻。不能假定相机每隔固定整数个物理步就严格等于标称帧率。

## P3.2 数据集格式

初期使用普通文件格式，不引入数据库。

建议：

```text
results/perception/datasets/
└── run_0001/
    ├── metadata.json
    ├── frames.jsonl
    ├── ground_truth.npz
    ├── left/
    │   ├── 000000.png
    │   └── 000001.png
    └── right/
        ├── 000000.png
        └── 000001.png
```

`metadata.json` 保存：

- 数据格式版本。
- 仿真后端和版本。
- 机器人模型版本。
- 相机配置和标定版本。
- 坐标系定义。
- 轨迹来源。
- 采样配置。
- 实验种子。
- 必要的软件和资源指纹。

`frames.jsonl` 保存：

- 左右帧路径。
- 帧序号。
- 相机采样时间。
- 实际仿真状态时间。
- 传感器有效性。
- 需要的关联索引。

`ground_truth.npz` 保存参考状态序列，包括：

- 球的真实世界坐标。
- 球的真实世界速度。
- 左右相机世界位姿。
- 必要的机器人头部姿态。
- 与图像帧对应的时间信息。

格式应简洁，避免保存大量重复状态。

## P3.3 真值与观测隔离

建立两条独立的数据通道：

**感知输入：**

- 左右 RGB 图像。
- 时间戳。
- 已配置的内外参。
- 明确允许使用的机器人状态。

**离线 Ground Truth：**

- 足球真实位置、速度。
- 精确相机位姿。
- 真实轨迹及事件。

禁止感知算法读取 Ground Truth 来直接输出足球三维位置。

可以设置专门的 Oracle 几何实验，但必须与正式图像感知实验分开，并在报告中明确标记。

## P3.4 数据验证

必须验证：

- 左右帧具有相同的采样时刻。
- 每帧均可找到匹配的标定和真值。
- 帧号与时间戳单调。
- 实际采样时间与配置的帧率调度一致，误差有记录。
- 记录的相机世界位姿与 MuJoCo 状态一致。
- 同一实验可重复生成相同的参考状态。
- 数据集可独立读取。
- 读取数据集不需要加载 MuJoCo。

### P3 验收标准

能够生成并重新读取一组包含左右图像、相机标定、时间戳和足球参考状态的完整数据。

评测程序可以只使用保存的数据集，而不需要重新运行仿真。

# P4：足球三维感知与轨迹估计基线

## P4.1 目标

验证新项目从传感器观测到足球三维状态的完整链路。

不追求最先进的检测算法。

初期选择简单、可解释、可测试的方法。

## P4.2 足球检测

第一版可以在专用测试场景中使用高对比度球体与简单图像处理方法。

建议：

- OpenCV 颜色分割。
- 轮廓提取。
- 球心像素估计。
- 基础置信度与有效性判断。

用于检测的球体外观可以是明确标记的简化实验设置，不能把简化视觉实验的性能当作自然场景检测能力。

若图像中找不到足球，返回无效观测，不允许用仿真真值补齐检测结果。

## P4.3 双目三维定位

使用左右图像检测到的球心，并结合内外参完成三角化。

首版可采用标准校正双目公式：

\[
Z=\frac{f_xB}{d}
\]

再计算：

\[
X=\frac{(u-c_x)Z}{f_x}
\]

\[
Y=\frac{(v-c_y)Z}{f_y}
\]

该公式适用于相应的校正双目坐标约定。未经校正的图像应使用完整投影矩阵或先执行校正处理。

结果输出：

```text
timestamp_s
position_camera_m
valid
confidence
```

需要时再转换到机器人本体坐标系。

测试必须覆盖视差接近零、球离开视野和错误匹配等异常情况。

## P4.4 速度与轨迹估计

初期采用最简单的可解释方法：

- 有效位置序列差分或基础滤波，估计速度。
- 使用恒速模型预测短时间轨迹。
- 可选增加恒重力模型作为第二条基线。

不引入深度学习轨迹预测模型。

明确区分：

- 相机坐标中的相对运动。
- 世界坐标中的足球运动。
- 相机本体运动带来的观测变化。

如果使用世界坐标速度，必须明确相机位姿与运动补偿的来源。

## P4.5 评测体系

至少报告：

| 指标 | 含义 |
|---|---|
| 二维检测成功率 | 能否从图像找到足球 |
| 三维位置误差 | 估计球心与真值之间的距离 |
| 速度估计误差 | 估计速度与参考速度的差异 |
| 固定时长预测误差 | 预测未来位置与真实未来状态的差异 |
| 有效观测时间 | 足球在本体相机中可被持续观察的时间 |
| 丢失跟踪率 | 跟踪中断的频次 |
| 处理耗时 | 检测、定位和预测各步骤执行时间 |

对 2D Oracle 输入和真实图像检测输入分别评测，用于区分检测误差与三角化误差。

不能使用渲染时间代替真实采集延迟，也不能将离线处理耗时直接宣称为真实相机端到端延迟。

## P4.6 完整 Demo

最终能够：

1. 选择一个轨迹源。
2. 加载 K1 与头部 ZED X。
3. 生成双目图像。
4. 从左右 RGB 图像检测足球。
5. 进行双目三维定位。
6. 根据历史估计速度。
7. 生成短时轨迹预测。
8. 与 Ground Truth 比较并输出报告。

至少验证一个正常可见的足球场景，以及一个足球离开相机视场的失败场景。

### P4 验收标准

形成从轨迹输入、图像生成到三维感知与误差评测的独立运行闭环。

正式报告必须区分：

- 理想几何验证。
- 简化图像检测结果。
- 双目三维定位结果。
- 速度和轨迹估计结果。
- 尚未验证的真实硬件性能。

# 6. 版本管理与执行规则

## 6.1 唯一开发仓库与目录

所有新代码、文档和测试仅写入 `Booster-K1-Goalkeeper` 仓库的 `Robot-Perception-Sim/` 子目录。

提交目标为 `Universeeeeeee/Booster-K1-Goalkeeper`。禁止提交到已弃用的 `Universeeeeeee/Robot-Perception-Sim` 远端。

父目录中的其他项目内容仅供参考/复用，不清理、重构、删除或格式化。提交前按路径核对 staged diff，确保全部修改位于本子目录。

## 6.2 分阶段提交

建议将各阶段形成独立提交：

| 阶段 | 建议提交说明 |
|---|---|
| P0 | `chore: bootstrap perception simulation repository` |
| P1 | `feat: add K1-mounted ZED X stereo cameras` |
| P2 | `feat: add trajectory sources and replay` |
| P3 | `feat: add synchronized stereo dataset recording` |
| P4 | `feat: add baseline ball perception and evaluation` |

如单个阶段改动过大，可以拆成多个有明确验收点的提交。

## 6.3 依赖与资产管理

- 复用父项目已验证依赖和环境，不增加重复依赖清单。
- 机器人模型使用固定上游提交。
- 第三方网格模型、外部数据和大型实验结果默认不提交。
- 不复制父目录既有项目的历史训练权重。
- 实验生成目录加入 `.gitignore`。
- 保存外部资源的来源和许可证。
- README 提供复用现有环境的最短运行步骤。

## 6.4 测试要求

每阶段执行：

```bash
.venv/bin/python -m pytest -q -c Robot-Perception-Sim/pytest.ini Robot-Perception-Sim/tests
```

相关脚本必须提供明确的 CLI 入口。

测试需要区分：

- 纯数据及数学单元测试。
- MuJoCo 模型集成测试。
- 需要 OpenGL 的图像渲染测试。

不能用静态代码检查代替真实渲染测试。

不能在缺少测试依赖时直接跳过相关测试并宣称功能完整通过。

复用原场景建立相机专项测试；不重复运行与本轮修改无关的运控和训练实验。新增相机必须通过动力学不变性和真实渲染检查。

# 7. Codex 分轮执行范围

初版已执行 P0 和 P1。2026-10-21 本轮执行 P2 最小物理射门采集：复用 `k1_goalkeeper.impact_validation.run_impact`、`preset_shots` 和官方站立控制，离线渲染 60 fps 的 0/10 ms 双目对照，保存时间戳、真值和曝光误差诊断。验收包含足球正常可见及离开视野、视频实际解码、物理轨迹复现和碰撞附近误差检查。不实现规则轨迹、CSV 回放或感知算法。

具体顺序：

1. 确认父仓库与子目录状态、已有资源和平台支持。
2. 在原场景上挂载相机，复用已有环境及资产。
3. 提供双目图像、标定和时间戳采集接口。
4. 完成静态渲染、几何和头部跟随验证。
5. 验证原场景动力学参数不变、修改仅在子目录。
6. 记录测试、截图、来源和实验假设。
7. 提交父仓库 Git commit，停止等待 P0–P1 审查。

P0–P1 完成报告必须包含：

- 感知子项目 Commit SHA。
- 修改文件及来源说明。
- 资源获取和复现命令。
- 左右目真实 MuJoCo 渲染截图。
- 测试数量、通过和失败情况。
- 相机名义参数及实验假设。
- 坐标系与基线验证结果。
- 仍未解决的问题。
- P2 的最小开发建议。

P2 的其他轨迹源及 P3–P4 完整功能不在当前执行范围内。

**最终目标：在优先复用原有仿真环境的前提下，逐步建立可从 macOS MuJoCo 迁移到 Linux Isaac Sim 的机器人本体视觉感知与评测平台。**
