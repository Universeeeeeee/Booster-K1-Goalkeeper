# K1 足球感知：Isaac Sim、ZED X SDK 与横移评测执行计划

## 1. 目标与本轮结论

将现有 MuJoCo 场景、Booster 官方 walk、足球轨迹和双目采集成果迁移至 Isaac Sim，使用 **ZED X 2.2 mm 广角版的仿真输入接入真实 ZED SDK**，评估机器人左右横移时的检测、深度、轨迹估计及动态模糊。最终交付可重复实验和模块化技术文档。

用户已明确：仅考虑仿真；执行环境是 VS Code 连接的 `lizhengran@robotic-4090`，使用 GPU0、GPU1；`pc@100.75.243.43` 仅用于参考本体感知/主动感知实现。实机采集、Jetson/GMSL 部署不属于本轮。旧 `docs/plan.md` 中“不实现 Isaac Sim 后端”的阶段性范围，由本次新需求更新；继续遵守仅在 `Robot-Perception-Sim/` 新增开发、复用父工程的边界。

本次交付是代码审计、官方资料核实、远端只读调查及实施计划；尚未在目标机安装 SDK、启动 Isaac 或完成跨引擎验证。下面的验收阈值均为拟定工程门槛，不是已有成绩。

实施顺序：**目标环境冻结 → 最小 SDK 接入验证 → 场景与 walk 迁移 → 足球事件覆盖 → 曝光与感知 → 横移对照 → 文档与复现包**。SDK 验证只需简单场景，不必等待完整机器人迁移；足球案例整理可以并行。

## 3. 环境与 SDK 技术关口（P0–P1）

### P0：目标机核查和可复现环境

在 `lizhengran@robotic-4090` 记录 GPU0/GPU1 型号、UUID、显存、驱动、占用、OS、CPU/RAM、可用磁盘、CUDA runtime、Isaac/Kit、ZED SDK、Python ABI、相关扩展和容器 runtime。不得把参考机的包版本当作目标机版本。

本轮已实查：目标机 Ubuntu 20.04.6、driver 575.57.08、8 张 RTX 4090，按用户要求仅用 GPU0/1；两卡总显存各 24564 MiB，检查时空闲显存为 23935/24066 MiB（资源随时间变化）。已装 Isaac Sim 4.5，未在 `/usr/local/zed` 或已有 Isaac 扩展发现 ZED。Docker 可执行程序存在，但当前用户访问 socket 被拒绝。默认先验证 **Isaac 4.5 + 官方扩展 v3.2.0 + 支持 Ubuntu 20.04 的历史 SDK**；SDK 具体版本须按官方下载包、CUDA和 ABI 冻结，不能照抄参考机 5.4.1。

具体首选 SDK 候选为 5.0.7 Ubuntu20/CUDA12 包；扩展 v3.2.0 的文档却要求 Ubuntu22，故当前组合尚未证实兼容。先做 GLIBC/GLIBCXX/Kit ABI 检查，再进行独立 SDK 接收进程验证；若不兼容，采用匹配的 Ubuntu22 用户空间/受支持环境，不覆盖共享宿主 OS/driver。详见 [调研证据与版本分支](isaac_zed_research_notes.md)。

执行产物：`results/environment/<run_id>/inventory.json`、`config/isaac/environment.lock.json`。锁定 Isaac、Kit、官方 ZED 扩展 tag/commit、SDK 安装包与校验值、Python、CUDA、YOLO 权重哈希、机器人和相机资产哈希。先跑兼容性检查与单相机空场景，再决定需要安装的最小依赖。

双 GPU 默认分工候选：GPU0 负责 Isaac 物理/渲染，GPU1 负责 SDK 深度与 YOLO；同时保留单 GPU0 的同机 IPC 对照。CUDA IPC/渲染缓冲共享可能要求同一物理设备，不能预设跨卡零拷贝可行；用 GPU UUID/PCI bus ID 校验映射。`CUDA_VISIBLE_DEVICES` 会重编号 CUDA 设备，Isaac/Vulkan 渲染设备选择必须另行核实。仅在测量显示有益时开启多 GPU 渲染；两张 24 GB 显存不当作单个 48 GB 池。

冻结物理 GPU0/1 的 UUID 白名单，多 GPU 渲染/自动选择默认关闭；检查 Isaac/Vulkan、物理后端、CUDA/SDK/YOLO 的实际进程归属，禁止自动占用 GPU2–7。启用双卡渲染时也必须显式限制到这两卡。

现有环境不原地升级。新组合采用隔离目录/环境；容器仍受宿主驱动约束。安装前按固定 Isaac 小版本查驱动表，禁止混用 6.0.0、6.0.1、latest 的要求。参考：[NVIDIA 6.0.0 系统要求](https://docs.isaacsim.omniverse.nvidia.com/6.0.0/installation/requirements.html)、[GPU 选择说明](https://docs.isaacsim.omniverse.nvidia.com/latest/installation/install_faq.html)。

### P1：真实 SDK 最小接入验证

官方存在 [ZED Isaac Sim 扩展](https://github.com/stereolabs/zed-isaac-sim)，因此优先用官方接入协议。必须审计固定版本实际发送内容，明确两条数据路径：

1. **正式 stereo 路径**：左右 RGB → 官方 transport → `sl.Camera` → SDK 双目深度/置信度 → YOLO/三维估计。
2. **Oracle 对照**：左 RGB + 仿真 GT depth → SDK 自定义深度入口，只用于通信/几何诊断。

正式成绩必须来自第一条；第二条成功不代表 SDK 从双目求深度成功。使用 stream/SVO 也不能凭“Camera.open 成功”推断来源正确。关闭 `Stream Depth`（若所选版本支持该选项），记录 transport、depth_source、插件设置和 SDK 输出；旧版本没有该开关时检查源码，不能硬套新版操作。

最小场景：带纹理平面置于 1/2/4 m，静态标记点、移动球和左右目。先 960×600/60 fps、无模糊，无机器人。执行以下验证：

- 官方消费者成功 `open/grab/retrieve_image/retrieve_measure`；持续取得至少 300 对有效帧，输出格式、视差方向、尺寸与单位正确。
- 用输出图像测量左右视差，并与独立场景距离比较；检查 RGB/深度/置信度同帧对应。
- 受控遮蔽/错位右图，SDK 深度应出现相应退化；将 GT depth 通道替换/禁用，正式输出不能随 GT 被直接替换。保留源码路径和配置证据。若官方入口不支持实验注入，使用纹理退化场景与 transport 抓取等独立证据组合，不以一个 getter 代替验证。
- 记录启动、首帧、连续帧、断流重连、暂停/重置时间戳行为；reset 后以新 episode 标识，禁止旧帧混入。
- 分别测同卡 IPC、跨卡可行方案、必要时 RTP/stream。实时吞吐不足时先证明离线确定性，不能降低分辨率后仍宣称原配置达标。

版本候选与目标机实查结果在附录中冻结。旧版 `v3.2.0` 的官方发布说明支持 Isaac 4.5/Kit 106.5，但它与 SDK 5.4.1 的具体组合仍需运行验证；新版功能不能倒推到旧版。[官方 v3.2.0 发布说明](https://github.com/stereolabs/zed-isaac-sim/releases/tag/v3.2.0)

**P1 失败出口**：若仅 GT depth 可用，保留其通信验证，明确正式目标未达成；优先换官方支持组合，再评估官方 streaming interface。普通 PNG、MP4 或自定义 NumPy 数组不能假定可直接喂给 SDK。限时 1–2 个工作日完成 spike；失败时产出复现日志和具体不兼容项，而不是继续搭完整场景掩盖问题。

## 4. 场景与官方 walk 迁移（P2）

新增 Isaac 后端放在本子目录，不重写父工程。先复用场景生成结果做 MJCF/USD 导入；若导入器丢失关节/惯量/碰撞，比较官方 URDF 路线，择一固定，不维护两套生产模型。

固定世界 X 沿球场长、Y 沿宽、Z 向上、单位 m/kg/s/rad。球场 22×14 m，右门 x=11，净口宽 3 m/高 2 m，球 r=0.11 m、m=0.43 kg。核查 22 个机器人关节、20 个策略动作关节、关节轴/限位、惯量、effort、初始姿态、碰撞过滤、球门静态属性和相机挂载。相机第一阶段沿用无质量/无碰撞组件，以维持现有 walk 基线；质量与真实挂载动力学另作实验，不暗中加入。

导入器只是资产转换。锁定 USD 的实际物理 variant/backend，核查导出层，不把新版 MJCF 导入一概等同于 PhysX；官方文档列有多自由度关节转换与策略迁移限制。[MJCF 导入器说明](https://docs.isaacsim.omniverse.nvidia.com/6.0.0/importer_exporter/ext_isaacsim_asset_importer_mjcf.html)

walk 适配保持：官方权重、观测次序与历史、动作缩放/滤波、task KP/KD、关节命名、50 Hz policy。初期采用 1 ms 物理步；按每步 PD 显式施加力矩时，禁用会叠加的隐式 joint drive。读取 delivered/applied effort 与位置差分做交叉验证。只有主循环推进时间；相机和 SDK 不另行推进物理。

按顺序验收：

| 检查 | 内容与通过条件 |
|---|---|
| 静态几何 | 具名关节数与模型一致；已知点投影正确；左右基线误差 ≤0.1 mm；无遗漏碰撞层 |
| 无机器人球 | 落球反弹、滚动、打柱/横梁，记录接触及速度翻转；用结果拟合接触材质 |
| 自由站立 | 30 秒无跌倒、NaN 或控制中止；复用现有高度/倾角门槛并报告实际值 |
| 横移 | body vy=±0.15/±0.20/±0.25，3 秒与长稳态窗；yaw=0/90/180° 验证符号与坐标 |
| 停止/反向 | 沿用 D 的末 2 秒逐轴 abs(vx)、abs(vy)≤0.05 m/s、abs(yaw rate)≤0.1 rad/s、高度≥0.45 m、倾角≤10°，至少连续 1 秒低速确认；核对恢复时间 |
| 迁移差异 | 报告实际位移、速度、接触/反弹、力矩与 MuJoCo 参考的差值；不能只用“没摔倒”判定等价 |

MuJoCo `solref/solimp` 与 PhysX restitution 不是数值映射。以反弹高度比、首次落地时间、滚动减速度、打框反向速度为标定目标；初拟误差门槛 5–10%，由基线与步长收敛实验在正式比较前冻结。跨引擎不要求逐位相同。高球拦截与新增运控训练不属于本轮重点。

## 5. 足球轨迹与事件覆盖（P3）

保留 `Shot` 和现有 `GoalDetector` 语义，在本子目录新增 `config/shots/perception_suite.json`。现有三个反弹初态直接作为起点；单位 m、m/s，spin=0：

| 名称 | 初始位置 | 初始速度 | 证据 |
|---|---|---|---|
| bouncing | (2, −0.35, 0.8) | (3, 0, 0) | G 冻结协议，历史无机器人 Goal |
| bounce_early_right | (0, 0.28, 0.45) | (2.6, 0, 0) | 同上 |
| bounce_late_left | (2, −0.42, 1.25) | (4, 0, 1) | 同上 |

每个场景先 absent 生成无防守标签，再用完全相同初态运行固定/站立/横移机器人。不能把“有机器人导致没有进球”与“射门本身偏出”混为一类。

覆盖至少以下事件族，每族先 3 个固定参数样例，再在通过后增加带种子的邻域扰动：

| 事件族 | 必须观测到的事实 |
|---|---|
| 地滚球/空中直入 | 完整球体越过目标门线且在净口内 |
| 一次/多次反弹后入门 | 独立 ground-contact episode、vz 转向、反弹发生在 Goal 前 |
| 左柱/右柱/横梁后弹出 | 具体门框 contact + 后续轨迹；未进门若尚未终止只能记 unresolved |
| 擦柱/碰横梁后入门 | 门框 contact 与最终 Goal 同时保存，不互斥 |
| 左偏/右偏/高出 | 整球出界，明确 miss 原因 |
| 反弹后射失/门前停球 | 反弹 + Miss，或足够观察窗后 stopped；Timeout 单独保存 |
| 机器人接触后入门/未入门 | contact 与 outcome 分离；若声明扑救成功需无机器人对照进球且充分观察 |
| 视觉失败 | 被遮挡、单目可见、出视野、再入视野，与物理 outcome 正交标注 |

采用 `event_sequence` 保存 contact_begin/contact_end、ground_bounce、post/crossbar、goal、pitch_exit、stopped、timeout；持续滚动接触不逐帧累加为多次反弹。球门边界用整球净口判定；右门完整越线中心 x=11.11 m，不能仅以球心越过 x=11 算 Goal。

对于擦框边缘、20 m/s 压力样例，检查时间步收敛与 CCD，避免穿透；基础范围先复用现有 2–12 m/s，有需求再扩展。保持既有无空气阻力/Magnus 的模型假设；不把未经标定的新空气模型作为必要前置工作。

验收：每个固定案例在目标后端确实产生声明事件，保存事件前后物理状态和视频；同后端同种子可重复；不允许以 preset 名称推断结果。最终标签与相机可见性、检测成功率分开。

## 6. 相机参数完整性与动态模糊（P4）

参数完整指每项有值或明确的 unsupported/not-modelled 状态、有来源、有单位、有实际验证，而不是编造出厂参数。

| 参数组 | 初始设置/处理 | 生效验证 |
|---|---|---|
| 型号/镜头 | 用户指定 ZED X、2.2 mm Wide、全局快门 | 官方资产/模型标识与版本 |
| 分辨率/帧率 | 960×600、60 fps；120 fps 为独立实验 | 实际输出尺寸、时间间隔与丢帧 |
| 内外参 | 基线 0.12 m；K、畸变、校正 R/P、左右变换、头部挂载 | SDK 返回值与渲染标记点/视差交叉验证 |
| 名义与官方配置 | 现有 HFOV110° 推得 fx=fy≈336.10 px、VFOV≈83.50°，仅用作 legacy 对照；切换官方资产需重新导出 K | 不强制把 110°/80° 同时塞进方形像素模型；不把 2.2 mm 直接当像素焦距 |
| 曝光 | 0 ms 理想对照，1/2/5/10 ms 扫描；固定曝光先于自动曝光 | 测运动标记拖影和亮度；0 ms 不作为真实硬件可设置值 |
| 增益/白平衡 | 固定值先行，记录 API 单位、允许范围、自动模式状态 | SDK 支持性与渲染实际变化分别记录；不支持的流控制明确标注 |
| 色彩/ISP | 色彩空间、gamma/tonemap、锐化、去噪、压缩、左右一致性 | 原始 PNG 与 SDK 接收图对照；RGB/BGR、rectified/raw 明确 |
| 光学/噪声 | 默认理想标定对照；畸变、光子/读出噪声只按有出处的模型启用 | 无实机参数时标注仿真假设，固定 seed |
| 深度 | SDK mode、min/max range、confidence 阈值、fill/filter 设置 | 不同距离/纹理球面的有效率和误差 |
| 时序 | 曝光开始/结束/中点、SDK时间、接收时间、估计完成时间 | 同帧对应、时钟映射、延迟与重复帧检查 |

关键限制：SDK 设置曝光成功，未必会改变仿真渲染；UI 上修改 shutter 也不证明运动模糊已生效。亮度曝光和 motion-blur shutter 在渲染器中可能分开控制，需按所选版本映射。[NVIDIA 相机属性](https://docs.omniverse.nvidia.com/materials-and-rendering/latest/cameras.html)、[运动模糊示例](https://docs.isaacsim.omniverse.nvidia.com/6.0.0/replicator_tutorials/tutorial_replicator_isaac_snippets.html)

实施两级成像：

1. **离线参考**：沿真实物理历史轨迹在曝光区间采样球、头部和机器人姿态，线性辐射域积分再转换输出；记录样本数与收敛误差。接触前后不使用恒速外推，也不跨碰撞仅用端点插值。先从 10 个子样本对齐旧实现，再用更密采样检查收敛。
2. **在线候选**：Isaac RTX motion blur。用同一段运动与离线参考比较拖影长度、方向、轮廓、背景、自运动与接触时刻；确认左右同步及未重复积分曝光。自动曝光/SDK Sim2Real 模型作为单独开关，避免不可解释地叠加。

全局快门仍有运动模糊；不默认添加 rolling-shutter 畸变。10 ms 曝光可用于 60 fps，但超过 120 fps 的 8.33 ms 周期，120 fps 实验应限制在合法曝光范围并计入读出约束。

对照必须包含“同曝光中点的瞬时帧”：旧 0/10 ms 共用开始时刻，会同时引入约 5 ms 的有效成像时间偏移；只比较它们不能把全部差异归因于模糊。保留旧对照用于回归，再增加时间对齐对照。子样本数至少比较 10/20/40 的收敛，不把离散重影误当真实拖影。

近轴量级检查：`blur_px ≈ fx × |v_perp_rel| × exposure / Z`，转动项约为 `fx × |omega| × exposure`，广角边缘需用完整投影。名义 fx=336.1、Z=3 m、10 ms：机器人平移 0.2 m/s 约 0.22 px；球横向 8 m/s 约 8.96 px；相机转动 1 rad/s 约 3.36 px。故不能只按横移命令速度讨论模糊，必须记录头部角速度、实际机体运动与足球相对速度。

## 7. 三维感知、坐标与时间（P5）

优先搭建可离线重放的链路，再接在线消费者：左 RGB YOLO → 球区域有效 SDK 深度/点云 → 三维球心估计 → 位姿变换 → 轨迹滤波。并行保留左右 YOLO/匹配→三角化作可解释对照，不先训练新检测器。

深度不能取 bbox 中心单像素：可能是背景、孔洞或模糊边界。使用收缩区域/可用分割 mask、置信度过滤、有效像素比例与稳健统计，失败显式返回 invalid。SDK 深度是可见表面，GT 是球心，两者存在约球半径量级偏差；球面拟合或受半径约束的中心模型必须明确几何假设，不简单给所有 Z 加 0.11 m。先报告表面误差，再报告中心估计误差。

统一 `T_AB` 表示 B→A、列向量、m，光学 X右/Y下/Z前。世界与机器人保留原工程约定。SDK 设置坐标系和单位后，再核对其实际输出；避免 SDK 已输出 world 又被重复变换。

```text
p_W(t) = T_WB(t) · T_BH(q_head(t)) · T_HC · p_C(t)
```

相机位姿必须对应观测曝光时间。原数据 `timestamp_s` 为曝光开始，增加 `exposure_mid_s` 而不改变旧字段含义。短曝光用中点近似；长曝光/碰撞有系统误差，要显式报告。保留 sim clock、SDK/image clock、host monotonic clock，测量偏移/漂移，不直接相减不同域时间戳。

帧最早在 `exposure_end_s` 后才可消费，另记 `available_at`；离线积分可以读取完整物理历史，但在线算法不能提前看到曝光尚未结束的帧。端到端主指标从曝光开始计到估计可用，另列从中点起算的观测年龄和纯处理延迟，均在已对齐的同一时钟域计算。

不能仅对相机系速度旋转：`v_W = v_camera_origin_W + R_WC (v_relative_C + omega_C × p_C)`。首版推荐先按各帧同步位姿把位置转入同一参考系，再用带时间戳滤波估速，避免漏掉平移和旋转项。

坐标方案做三组消融：

| 方案 | 用途 | 限制 |
|---|---|---|
| camera-relative | 检测/三角化直接基线 | 不直接称作世界速度或跨帧静止坐标 |
| local odom + 头部关节 | 推荐可部署结构；连续局部参考系降低全局定位依赖 | 记录漂移/丢定位，门相对位姿须另有来源 |
| world | 与球门及机器人统一评测 | 精确仿真 T_WB 仅为 Oracle；使用估计位姿时标来源和不确定度 |

正式算法仅接图像、标定、时间戳、明确允许的估计机器人/头部状态。真值球位姿、分割标签、精确相机/机器人世界位姿进入独立评测通道；Oracle 实验单独命名。加入“静止球+机器人横移/转头”试验，正确补偿后球世界速度应近零；yaw=0/90/180°、负视差、单目丢失、NaN depth、过期位姿均须测试。

同步误差独立扫描 0/1/5/10 ms；位姿插值只能使用处理时已到达的状态，若等待未来时刻位姿再插值，记录额外延迟，不称为零延迟因果输出。测距预算用 `sigma_Z≈Z²·sigma_d/(fx·B)` 检查：名义配置在 10 m、1 px 视差误差下约 2.48 m，仅是解析灵敏度而非实测，不能对整个球场预设厘米级精度。

跟踪首版为恒速/恒重力 Kalman 或最小滤波基线；检测到反弹创新时允许重置/切换模型，不能跨反弹强行平滑。落点预测只用历史观测，不用复制真实仿真状态的球预测器冒充视觉能力。

## 8. 横移实验与优化顺序（P6）

先锁定无机器人足球事件，再锁定 walk 迁移，再做视觉评测。相机观测中的球丢失可能是出视野，不能全部归因于 YOLO。

分阶段矩阵，避免一开始全因子爆炸：

1. 静站与 body vy=±0.2 m/s，曝光 0/10 ms，选择直入、反弹入门、打框、偏出、高球、出视野 6 类，每类 3 组不同且冻结的 Shot 参数：108 组。同一 Shot 的曝光对照复用同一物理历史。
2. 对失败类别扫描 vy=±0.15/±0.25、1/2/5 ms 曝光、头部静止/自然步态摆动/预设转头、距离与光照；120 fps 单独比较，不默认实时可达。
3. 每个代表性工况增加至少 10 个独立采样且保存完整初态的 Shot，按整次射门统计区间，避免把大量相邻视频帧当独立样本。开发与最终评测 Shot/seed 分离。现有 `Shot.seed` 只是元数据；只有显式随机采样器使用 seed 生成不同参数时才产生新工况，不能只改 seed 重复同一发射充数。

至少报告：可见帧检测 recall/precision（声明 IoU 门槛）、各距离二维像素误差、深度有效率、三维中心 median/P95、速度 RMSE、50/100/200 ms 预测误差、连续丢失时长、重新捕获时间、反弹/打框附近误差、实测横移速度、GPU显存/利用率、仿真 RTF、处理吞吐和端到端 P50/P95。

可见性分母由独立 GT 可见面积/遮挡规则冻结，GT 只做评测。无球帧评测误报；无效深度不得被从统计中静默删除。轨迹边界点与 episode reset 不能串轨迹。

拟定初始验收：

- 理想静态几何点重投影 ≤1 px；机器人运动下静止球的 Oracle 补偿位置 P95≤1 cm（专用无模糊解析/标记点实验）。
- 1–4 m、球双目可见且有效直径≥10 px、普通光照、曝光≤5 ms 的冻结子集：检测 recall≥95%，三维中心 P95≤0.10 m；这是目标值，需记录模型/深度测量能力，若不可达保留失败原因与实测结果。
- 相同冻结子集，横移相对静站 recall 下降≤5 个百分点、P95 三维误差增幅≤25%；绝对误差接近零时同时报告差值以避免比例失真。
- 60 fps 采集/消费吞吐、SDK深度与检测延迟分别测量；先以无持续队列堆积为准。拟定端到端 P95≤50 ms，是否足够还需结合球速与可用响应时间，不能视为守门成功保证。
- 10 ms、高速/远距离/强模糊作为压力集完整报告，不提前承诺与理想子集同等精度。

优化按归因顺序：**同步/坐标错误 → 视野与头部姿态 → 曝光/亮度 → 深度区域与球心定义 → detector 输入/阈值 → 过滤与预测 → 必要时微调检测器**。每次只改变一个主因素，用同一冻结数据复测。若做训练，按 shot/场景划分训练与测试，不能随机拆相邻帧。无需重新训练 walk。
